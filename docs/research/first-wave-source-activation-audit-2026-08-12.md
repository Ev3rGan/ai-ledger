# First-wave Source Definition activation audit

- Checked: 2026-08-12
- Scope: the 16 first-wave Source Definitions named in GitHub Issue #3 and the Parent Spec (#1)
- Evidence rule: first-party Publisher pages, policies, robots files, and official APIs only
- Legal posture: conservative engineering recommendation, not legal advice; an `approved` conclusion approves only the explicitly stated discovery and storage tier

## Conclusions

| Conclusion | Count | Source Definitions |
| --- | ---: | --- |
| `approved` | 6 | Google AI, Hugging Face Blog, GitHub AI and ML, GitHub Changelog, arXiv AI queries, curated GitHub Releases |
| `metadata-only` | 5 | OpenAI News, Microsoft Research, DeepSeek Changelog, Machine Heart, Qbitai |
| `blocked` | 2 | Meta AI, NVIDIA Generative AI |
| `needs-verification` | 3 | Anthropic News, Google DeepMind, Qwen Blog |

These are activation-policy conclusions, not claims that adapters work. `metadata-only` means the system may retain discovery metadata (canonical URL, title, publication/update time, Publisher, category, and a source-supplied feed description when present) but not the fetched article body. Unless a row expressly says otherwise, public output is limited to an original AI-marked paraphrase, a canonical source link, and at most a short attributed excerpt approved under the configured policy. Images, video, complete source text, and feed/body mirroring are excluded.

The executable manifest records an intended adapter type, cursor contract, and health policy for every Source Definition without implementing an adapter. It also converts “short excerpt” into a machine-checkable cap: 280 Unicode characters for approved feed or release excerpts, 1,000 for the CC0 arXiv abstract field, and zero for every other Source Definition.

## Cross-definition operating rules

1. `approved` does not authorize unrestricted crawling or redistribution. The configured adapter must use the stated feed/API first, honor the stated rate limit, and stay inside the stated storage tier.
2. Every fetch must still enforce HTTPS, redirect validation, private-network denial, MIME and size limits, timeouts, and untrusted-content handling. A policy approval never bypasses fetch security.
3. Store the fetched policy/robots observation date and content hash with each Source Definition. A material change forces re-review before the next Collection Run.
4. A 401/403/429, CAPTCHA/challenge, explicit opt-out header, robots conflict, takedown request, repeated parse failure, or unexpected redirect pauses that Source Definition without deleting historical accepted knowledge.
5. Raw extracted body text remains private even when storage is allowed. Public pages use AI-marked original summaries, bounded policy-approved excerpts, and canonical source links.
6. Curated GitHub Releases is one Source Definition, not one definition per repository. Its allowlist and repository-specific tag/license/build filters are versioned configuration. It remains separate from new-repository discovery.

## Verification still required before live activation

- This desk review was not executed from the selected Hong Kong production region. Hong Kong reachability, mainland-user implications, latency, redirects, and observed 401/403/429 behavior remain unverified for all 16 definitions.
- No acquisition adapter was implemented or run. Parser fixtures, canonical URL extraction, publication/update timestamp behavior, MIME handling, pagination/cursors, extraction quality, update frequency, and duplicate rate remain unverified.
- The first production-like review must capture the exact effective robots and terms documents, response headers, and hashes. This is especially required for the three `needs-verification` Source Definitions.
- The review does not select an extraction provider and does not authorize production credentials. GitHub public Release access can start unauthenticated at low volume; any later token must be a least-privilege secret and must not be committed.
- Publisher permissions, policies, endpoints, and site structures can change. Re-run this audit before activation and on every detected policy or interface change.
